# Day 3-03D：从普通按钮到提交按钮

开始条件：阶段复习 A、B 已验收。这节只回答“点击按钮后，为什么会进入表单提交流程”，暂不写 `form.on` 和 `data.field`。

## 先回忆浏览器本来会做什么

你在 `7.day3-练习.html` 写过纯 HTML 表单：`<form>` 包住带 `name` 的输入框和 `type="submit"` 按钮。点击后，浏览器先检查 `required`，再按默认方式提交；没有专门处理时，页面可能跳转或刷新。这不是 Layui 发明的行为。

而复习页中的按钮是：

```html
<button type="button" class="layui-btn">查看填写说明</button>
```

`type="button"` 的意思是普通按钮。即使它在 `<form>` 里面，点击也不会自动提交表单。`class="layui-btn"` 只负责外观，不会把普通按钮变成提交按钮。

## Layui 又加了什么

以后要用的提交按钮是：

```html
<button type="submit" class="layui-btn" lay-submit lay-filter="studentSubmit">
    保存学生
</button>
```

| 片段 | 来源 | 作用 |
| --- | --- | --- |
| `type="submit"` | HTML | 按钮具有原生提交行为 |
| `class="layui-btn"` | Layui CSS | 按钮外观 |
| `lay-submit` | Layui form | 告诉 form 模块此按钮触发提交事件 |
| `lay-filter="studentSubmit"` | Layui form | 给这次提交事件取一个匹配名 |

`studentSubmit` 是自己起的标识，不是 JavaScript 变量，不用 `#`，也不是 `name` 字段。下一课 JS 会用完全相同的文字匹配它。

## 验证规则放在哪

例如姓名输入框：

```html
<input name="studentName" class="layui-input" lay-verify="required">
```

`lay-verify="required"` 是 Layui 的必填验证规则，写在需要验证的控件上。它与纯 HTML 的 `required` 都能表达“必填”，但来源与处理机制不同。当前 Layui 练习统一用 `lay-verify`，不要同时混用两套规则来猜是谁弹出的提示。性别下拉框的第一个选项 `value=""` 代表尚未选择，适合做必填检查。

## 这节的一个小实验

继续修改 `9.复习-学生信息页.html`：保留“查看填写说明”这个 `type="button"` 按钮；在同一表单中另加一个“保存学生”提交按钮，写上上表的四个部分。给姓名输入框和性别下拉框分别加 `lay-verify="required"`。**先只测试空白表单点击“保存学生”**：应出现必填提示；普通“查看填写说明”仍然只显示原来的 `layer.msg`。

现在还没有提交回调。填完整再点“保存学生”可能发生浏览器默认跳转或刷新；**暂时不要这样测试**。下一课会先登记回调并阻止默认跳转，然后再测试完整填写。

能说清“普通按钮”和“提交按钮”的差异、空白时为什么提示必填，就完成本小节。官方依据：[Layui form 的属性、验证和提交事件](https://layui.dev/docs/2/form/)。
