# Day 3-03C：用命名函数连接表单提交

> 历史对照（2026-09-21）：本讲义一次引入两个命名函数，暂不作为练习。现在从 [阶段复习](0921-01-复习-把Day1到Day3前半段串起来.md) 开始，把提交按钮、回调、`data.field` 拆成 [03D](0921-02-Day3-03D-从普通按钮到提交按钮.md)、[03E](0921-03-Day3-03E-登记提交回调并留在页面.md)、[03F](0921-04-Day3-03F-看懂data-field.md)。

## 一、这节只解决什么

把原来的嵌套写法：

```javascript
layui.use(["form", "layer"], function () {
    form.on("submit(studentSubmit)", function (data) {
        // 提交处理
    });
});
```

拆成两个有名字的函数：

```text
afterModulesReady     模块准备好后执行
handleStudentSubmit   表单验证通过后执行
```

先看清谁调用谁，再考虑匿名函数简写。

## 二、完整的命名函数版本

```javascript
function handleStudentSubmit(data) {
    console.log(data.field);

    layui.layer.msg("表单验证通过", {
        icon: 1,
        time: 2000
    });

    return false;
}

function afterModulesReady() {
    const formModule = layui.form;

    formModule.render();
    formModule.on("submit(studentSubmit)", handleStudentSubmit);
}

layui.use(["form", "layer"], afterModulesReady);
```

代码书写顺序不等于执行顺序。两个函数先被定义和保存，真正的执行由后面的事件决定。

## 三、第一条回调链：模块准备完成

```javascript
layui.use(["form", "layer"], afterModulesReady);
```

这里现在调用的是 `use(...)`，但没有调用 `afterModulesReady`。

```text
use 收到模块数组
→ use 准备 form 和 layer
→ 模块准备完成
→ use 调用 afterModulesReady
```

因此：

```text
afterModulesReady 是交给 use 的回调函数
调用者是 use
调用时间是模块准备完成后
```

## 四、afterModulesReady 内部做什么

```javascript
const formModule = layui.form;
```

取得 form 模块对象，保存到变量 `formModule`，没有函数调用。

```javascript
formModule.render();
```

调用 form 模块对象的 `render` 方法，渲染表单。

```javascript
formModule.on("submit(studentSubmit)", handleStudentSubmit);
```

调用 `on` 方法，登记一条规则：

> 当 `studentSubmit` 这次表单提交通过验证时，请调用 `handleStudentSubmit`。

这里传入的是：

```javascript
handleStudentSubmit
```

没有 `()`，所以此时不执行提交处理函数。

## 五、第二条回调链：表单提交

HTML 按钮：

```html
<button
    type="submit"
    lay-submit
    lay-filter="studentSubmit"
>
```

JavaScript：

```javascript
formModule.on("submit(studentSubmit)", handleStudentSubmit);
```

`studentSubmit` 把 HTML 和 JavaScript 对应起来：

```text
用户点击提交按钮
→ form 模块发现 lay-submit
→ 根据 lay-verify 执行验证
→ 验证通过
→ 匹配 lay-filter="studentSubmit"
→ form 模块调用 handleStudentSubmit
```

因此：

```text
handleStudentSubmit 是交给 formModule.on 的回调函数
调用者是 form 模块
调用时间是指定提交事件验证通过后
```

## 六、data 是谁给的

函数定义：

```javascript
function handleStudentSubmit(data) {
```

`data` 是参数名，由我们命名。它的值不是我们手写的，而是 form 模块调用这个函数时传进来的提交信息。

可以把内部调用想象成：

```javascript
handleStudentSubmit(本次提交信息);
```

因此函数内部可以读取：

```javascript
data.field
```

`field` 是提交信息对象中的一个属性，它保存表单字段对象。

```text
对象的键：来自 input/select 的 name
对象的值：来自用户输入或 option 的 value
```

## 七、为什么直接写 layui.layer.msg

```javascript
layui.layer.msg("表单验证通过");
```

这一版没有再创建 `layer` 变量，是为了减少一层变量关系。

拆开看：

```text
layui.layer       取得 layer 模块对象
msg               模块对象的方法
msg(...)          调用方法
```

`layer` 已经包含在 `layui.use(["form", "layer"], ...)` 的模块数组中，因此使用回调执行和表单提交发生时，它已经准备好了。

以后熟悉后再写常见简写：

```javascript
const layer = layui.layer;
layer.msg(...);
```

## 八、return false 返回给谁

```javascript
return false;
```

它不是返回给用户，也不是返回给数据库。

`handleStudentSubmit` 是 form 模块调用的，所以返回值会回到 form 模块。Layui 将 `false` 理解为：

> 不要继续执行浏览器原生的表单提交。

于是页面不会刷新或跳转。

对比：

```text
纯 HTML：验证通过 → 浏览器默认提交 → 页面刷新/跳转
当前 Layui：验证通过 → 回调处理数据 → return false → 停止默认提交
```

## 九、完整执行时间线

```text
页面加载
→ 保存两个命名函数
→ 调用 layui.use
→ use 准备 form、layer
→ use 调用 afterModulesReady
→ render 表单
→ on 登记 handleStudentSubmit

用户填写并点击保存
→ form 模块验证
→ form 模块调用 handleStudentSubmit(data)
→ 输出 data.field
→ 调用 layui.layer.msg
→ return false 阻止默认刷新
```
